# CLAUDE.md

This file provides guidance for Claude Code when working on this project.

## Project Overview

W3C MCP Server — an MCP (Model Context Protocol) server that exposes W3C/WHATWG/IETF
web specifications (spec metadata, WebIDL, CSS properties, HTML elements) to AI
assistants. Data comes from official npm packages (`web-specs`, `@webref/*`); this
server adds caching, search, and MCP-shaped tools on top of them.

## Common Commands

```bash
npm run build      # Compile TypeScript
npm run dev        # Watch mode compilation
npm test           # Run Vitest — run before committing
npm run check      # Biome lint + format (auto-fix)
```

## Code Conventions

### Error handling

Throw the custom error classes in `src/errors/index.ts` (`SpecNotFoundError`,
`WebIDLNotFoundError`, `CSSNotFoundError`, `ElementsNotFoundError`) and let
`toolHandler()` in `src/index.ts` format them via `formatErrorResponse()`.
Not-found errors should include up to 10 spec-name suggestions generated by
`src/utils/suggestions.ts`.

### Tool registration (MCP SDK v2)

Tools are registered in `createServer()` (`src/index.ts`) with
`McpServer.registerTool(name, { description, inputSchema }, toolHandler(...))`.
`inputSchema` is the zod object from `src/schemas/index.ts` — the SDK validates
arguments against it before the handler runs and generates the `tools/list`
JSON Schema from it, so put parameter descriptions in `.describe()` on the zod
fields rather than in a separate JSON Schema. Startup goes through
`serveStdio()`, which serves both the `initialize` (2024-11-05 … 2025-11-25)
and `server/discover` (2026-07-28) openings from the same factory.

### Data mapping

Use `toSpecSummary()` / `toSpecSummaries()` from `src/utils/mapper.ts` for any
`SpecDetail → SpecSummary` conversion. Do not reimplement this mapping inline.

### Imports (ESM)

- Use the `.js` extension on local relative imports (e.g. `from './foo.js'`) — this is required for Node ESM, even in `.ts` source.
- Use the `node:` prefix for built-ins (`node:fs`, `node:path`, ...).

### Constants and hardcoding

No hardcoded URLs, limits, or version strings. Put them in `src/constants/`. The
server version is read dynamically from `package.json` at startup
(`src/index.ts`).

### Dependencies

`@webref/*` and `web-specs` ship frequent non-breaking updates; keep them on
caret ranges (`^`) and let Dependabot open weekly PRs to follow upstream.

`@types/node` tracks the minimum supported Node major (`engines.node`, currently
22), not the newest Node. Dependabot is configured to ignore its major updates.

TypeScript 7 (Go-based `tsc`) does not pick up `@types/*` automatically;
`tsconfig.json` lists `"types": ["node"]` explicitly. Keep it when editing the
config.

## Release

Publishing to npm uses **Trusted Publisher (OIDC)** — there is no `NPM_TOKEN`
secret. The publish job in `.github/workflows/ci.yml` runs on `v*` tag pushes
with `id-token: write` and invokes `npx -y npm@latest publish --provenance`
(npm bundled with Node 22 is too old for Trusted Publisher, so we shell out to
the latest npm). Configure the trusted publisher at
<https://www.npmjs.com/package/@shuji-bonji/w3c-mcp/access>.

Release steps:

1. Bump `version` in `package.json`.
2. `git tag vX.Y.Z && git push --tags`.
3. CI publishes automatically if the build and initialize handshake pass.
